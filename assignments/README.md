# מטלה 1: מערכת הגשה ושיפוט עמיתים

שני חלקים:

- **העמוד** `assignments/01-estimators/` באתר הקורס: כניסה, הגשת שאלה ושאלון, שיפוט וציון.
- **השרת** `assignments/apps-script/` (Google Apps Script שמחובר ל-Google Sheet). ה-Sheet הוא מסד הנתונים וגם ממשק הניהול, דרך התפריט "מטלה 1". קובצי ה-PDF נשמרים בתיקייה פרטית ב-Drive, והעמוד מקבל אותם דרך הסקריפט. כך סטודנטים לא רואים מי העלה ולא מקבלים גישה ל-Drive.

תצוגה מקדימה בלי שרת: לפתוח את העמוד עם `?demo` (או כשה-`API_URL` ריק). בפס העליון אפשר לעבור בין השלבים.

## הקמה (פעם אחת)

1. ליצור Google Sheet חדש. עדיף בחשבון האוניברסיטה: המכסה היומית של מיילים גבוהה יותר.
2. **File ← Settings**: אזור זמן `(GMT+02:00) Jerusalem`.
3. **Extensions ← Apps Script**:
   - להחליף את התוכן של `Code.gs` בקובץ `apps-script/Code.gs`.
   - להוסיף קובץ בשם `Logic` (הכפתור + ← Script) ולהדביק בו את `apps-script/Logic.gs`.
   - **Project Settings**: אזור זמן Jerusalem.
   - לשמור.
4. לרענן את ה-Sheet. בתפריט **מטלה 1 ← 1. הגדרה ראשונית** (בפעם הראשונה Google יבקש הרשאות). נוצרים כל הגיליונות ותיקיית Drive פרטית.
5. בגיליון **Students** להדביק: `student_id`, `name`, `email`. את הרשימה אפשר לייצא מהמודל. מייל נחוץ רק במצב `code`. אפסים מובילים בת"ז לא משנים.
6. בגיליון **Settings**:
   - `AUTH_MODE`:
     - `code` (ברירת מחדל): קוד אישי נשלח במייל דרך **מטלה 1 ← 2. שליחת קודים**.
     - `register`: בכניסה הראשונה הסטודנט בוחר סיסמה. אפשר להירשם רק עם ת"ז שמופיעה ב-Students.
   - מועדים: `SUBMIT_DEADLINE` (ברירת מחדל: 21.11.2026 23:59), `REVIEW_DEADLINE` (ברירת מחדל: 28.11.2026 23:59). `REVIEW_OPEN` ריק = השיפוט נפתח כשמריצים הקצאת שופטים.
   - `SITE_URL`: כתובת עמוד המטלה. היא נכנסת למייל של הקודים.
7. פרסום הסקריפט: **Deploy ← New deployment ← Web app**, עם Execute as: **Me** ו-Who has access: **Anyone**. להעתיק את ה-URL.
8. להדביק את ה-URL ב-`API_URL` בראש הסקריפט בקובץ `assignments/01-estimators/index.html`.
9. כדי שהמטלה תופיע באתר: ב-`lectures.json`, תחת `assignments`, לשנות ל-`"published": true`. אחר כך `python tools/build.py --check` ו-push.

## במהלך המטלה

| מתי | מה עושים |
|---|---|
| לפני הפתיחה | אם `AUTH_MODE` הוא `code`: **2. שליחת קודים**. אפשר להריץ שוב, ונשלח רק למי שעוד לא קיבל. |
| אחרי `SUBMIT_DEADLINE` | **בדיקת זוגות** (מראה סתירות בבחירת שותפים), ואז **3. הקצאת שופטים**. השיפוט נפתח ב-`REVIEW_OPEN` (או מיד, אם הוא ריק). |
| אחרי `REVIEW_DEADLINE` | **4. רענון רשימת הטעויות**, ואז בגיליון Flags לסמן `confirmed` = TRUE או FALSE לכל סימון. |
| | **5. חישוב ציונים**. התוצאה בגיליון Grades. |
| כשמוכנים לפרסם | ב-Settings: `RESULTS_PUBLISHED` = TRUE. |
| למטלה 2 | **6. ייצוא נתונים אנונימיים**. נוצרים Export_Students ו-Export_Reviews, ומורידים מהם CSV. |

**חוקי הציון** (`Logic.gs`):
- 3 נקודות על השאלה, אלא אם אושרה בה טעות.
- 0–2 נקודות לפי שליש הדירוג הממוצע. מי שבדיוק על הגבול בין שני שלישים מקבל את השליש הגבוה. את הנקודות האלה מקבל רק מי שהשלים את השיפוט שלו.
- בונוס `BONUS_PER_FLAG` לכל טעות שאושרה, עד `BONUS_CAP`.
- דירוגים נספרים רק מסטים שהוגשו במלואם.

## תחזוקה

- **שינוי בקוד הסקריפט**: Deploy ← Manage deployments ← עריכה ← Version: New version. ה-URL לא משתנה.
- **איפוס סיסמה**: למחוק את `secret_hash` ואת `salt` בשורה של הסטודנט. במצב `register` הוא נרשם מחדש. במצב `code` מריצים שוב את שליחת הקודים.
- **הארכה לסטודנט**: אין מנגנון כזה. אפשר להאריך את המועד לכולם ב-Settings.
- **שותף**: הסטודנט מקליד את השם המלא של השותף. השרת משווה אותו לעמודה `name` ב-Students, בלי תלות בסדר המילים, ברווחים או בגרש. שם שלא נמצא מחזיר שגיאה, ואם יש שני סטודנטים באותו שם הסטודנט מתבקש לפנות למתרגל.
- **פרטיות**: הת"ז והשמות נמצאים רק ב-Sheet, ורשימת הסטודנטים לא נשלחת לדפדפן. בייצוא אין ת"ז ואין שמות, והשורות בסדר אקראי. בהעלאה, השרת מוחק מה-PDF את שדות המחבר, הכותרת, הנושא ומילות המפתח במאפייני הקובץ (גם ב-XMP), כך שהשופטים לא רואים שם במאפיינים. פתיחת הפתרון נרשמת ב-Assignments (`solution_opened_at`) ונכנסת לייצוא; היא לא מוצגת לסטודנטים ולא משפיעה על הציון.
